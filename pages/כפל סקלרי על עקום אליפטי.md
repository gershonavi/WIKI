# כפל סקלרי על עקום אליפטי

**כפל סקלרי על עקום אליפטי** הוא הפעולה של חיבור חוזר של נקודה על [עקום אליפטי](https://he.wikipedia.org/wiki/%D7%A2%D7%A7%D7%95%D7%9D_%D7%90%D7%9C%D7%99%D7%A4%D7%98%D7%99) לעצמה. זו הפעולה המרכזית בקריפטוגרפיה של עקומים אליפטיים (ECC). בספרות מופיע גם השם **כפל נקודות על עקום אליפטי** (elliptic curve point multiplication), אבל השם הזה עלול ליצור רושם מוטעה של כפל בין שתי נקודות, ולכן עדיף לדבר על כפל ב[סקלר](https://he.wikipedia.org/wiki/%D7%A1%D7%A7%D7%9C%D7%A8).

## יסודות

בהינתן עקום $`E`$ שמוגדר על ידי משוואה מעל [שדה סופי](https://he.wikipedia.org/wiki/%D7%A9%D7%93%D7%94_%D7%A1%D7%95%D7%A4%D7%99) (למשל $`E: y^2 = x^3 + ax + b`$, עקום בצורת ויירשטראס), כפל של נקודה מוגדר כחיבור חוזר שלה לאורך העקום. מסמנים $`nP = P + P + \cdots + P`$ ($`n`$ מחוברים) עבור סקלר (שלם) $`n`$ ונקודה $`P = (x, y)`$ על העקום. מגדירים גם $`0P = \mathcal O`$ ו-$`(-n)P = -(nP)`$.

הביטחון של ECC מודרנית נשען על הקושי לקבוע את $`n`$ מתוך $`Q = nP`$ כאשר $`Q`$ ו-$`P`$ ידועים ו-$`n`$ גדול. זו **בעיית הלוגריתם הבדיד על עקום אליפטי**, בהקבלה ל[בעיית הלוגריתם הבדיד](https://he.wikipedia.org/wiki/%D7%91%D7%A2%D7%99%D7%99%D7%AA_%D7%94%D7%9C%D7%95%D7%92%D7%A8%D7%99%D7%AA%D7%9D_%D7%94%D7%91%D7%93%D7%99%D7%93) בחבורה הכפלית של שדה סופי, שעליה נשענות מערכות כמו [דיפי–הלמן](https://he.wikipedia.org/wiki/%D7%A4%D7%A8%D7%95%D7%98%D7%95%D7%A7%D7%95%D7%9C_%D7%93%D7%99%D7%A4%D7%99-%D7%94%D7%9C%D7%9E%D7%9F). החיבור של שתי נקודות (או של נקודה לעצמה) נותן נקודה שלישית שמיקומה אינו קשור באופן גלוי למיקום של שתי הראשונות, וחזרה על כך פעמים רבות נותנת נקודה $`nP`$ שיכולה להיות כמעט בכל מקום. אינטואיטיבית זה דומה למעגל: אם מוסיפים לזווית של נקודה $`P`$ על מעגל 42.57 מעלות, הנקודה החדשה עדיין "לא רחוקה" מ-$`P`$; אבל אחרי הוספה של 1000 או 1001 פעמים 42.57 מעלות, כבר צריך חישוב מורכב יותר כדי לשחזר את מספר הצעדים. על עקום אליפטי טוב לא ידוע אלגוריתם שמשחזר את $`n`$ מהר משמעותית מ-$`O(\sqrt{\#E})`$ צעדים (למשל אלגוריתם צעד-תינוק צעד-ענק או אלגוריתם ρ של פולארד), ולכן המאמץ אינו מעשי כאשר הסדר של $`P`$ גדול.

הנקודה החשובה היא שהכיוון "הישר" קל: את $`nP`$ אפשר לחשב בערך ב-$`\log_2 n`$ פעולות של הכפלה וחיבור, ולא ב-$`n-1`$ חיבורים. רוב הערך עוסק בשיטות לעשות זאת.

## פעולות על נקודות

יש שלוש פעולות בסיסיות על נקודות של עקום אליפטי: חיבור, הכפלה (חיבור נקודה לעצמה) ושלילה.

### הנקודה באינסוף

הנקודה באינסוף $`\mathcal O`$ היא [איבר היחידה](https://he.wikipedia.org/wiki/%D7%90%D7%99%D7%91%D7%A8_%D7%99%D7%97%D7%99%D7%93%D7%94) של החבורה. חיבור שלה לכל נקודה נותן את הנקודה עצמה, כולל חיבור שלה לעצמה:



```math
\mathcal O + \mathcal O = \mathcal O, \qquad \mathcal O + P = P.
```

 את הנקודה באינסוף מסמנים לפעמים גם 0.

### שלילה

הנגדית של $`P`$ היא הנקודה $`-P`$ שמקיימת $`P + (-P) = \mathcal O`$. בעקום מהצורה $`y^2 = x^3 + ax + b`$, לנגדית אותה קואורדינטת $`x`$ וקואורדינטת $`y`$ נגדית:



```math
-(x, y) = (x, -y).
```

 לכן החיסור זול בדיוק כמו החיבור, עובדה שהשיטות של הצגה לא-סמוכה (NAF) בהמשך מנצלות.

### חיבור

עבור שתי נקודות שונות $`P`$ ו-$`Q`$, הסכום $`R = P + Q`$ הוא השיקוף (הנגדית) של נקודת החיתוך השלישית של הישר דרך $`P`$ ו-$`Q`$ עם העקום. עבור $`E: y^2 = x^3 + ax + b`$ ו-$`(x_p, y_p) + (x_q, y_q) = (x_r, y_r)`$:



```math
\lambda = \frac{y_q - y_p}{x_q - x_p}, \qquad x_r = \lambda^2 - x_p - x_q, \qquad y_r = \lambda(x_p - x_r) - y_p.
```

 הנוסחאות נכונות כאשר אף אחת מהנקודות אינה $`\mathcal O`$ ולנקודות קואורדינטות $`x`$ שונות. אם $`x_p = x_q`$ ו-$`y_p = -y_q`$, הנקודות נגדיות והסכום הוא $`\mathcal O`$. הטיפול במקרים האלה חשוב בפועל, למשל באלגוריתם האימות של ECDSA, שבו ערך הגיבוב עשוי להיות אפס.

### הכפלה

כאשר $`P = Q`$ אין ישר מוגדר היטב דרך שתי הנקודות, ולוקחים את המקרה הגבולי: ה[משיק](https://he.wikipedia.org/wiki/%D7%9E%D7%A9%D7%99%D7%A7) לעקום ב-$`P`$. גזירה סתומה של משוואת העקום נותנת את השיפוע



```math
\lambda = \frac{3x_p^2 + a}{2y_p},
```

 ואת $`x_r, y_r`$ מחשבים באותן נוסחאות כמו בחיבור (עם $`x_q = x_p`$). אם $`y_p = 0`$, המשיק אנכי ו-$`2P = \mathcal O`$.

## שיטות לכפל סקלרי

הדרך הישירה היא חיבור חוזר, אבל היא דורשת $`n - 1`$ חיבורים, כמות לא מעשית עבור $`n`$ בן 256 ביטים. כל השיטות שלהלן משתמשות בהצגה הבינארית (או בהצגה דומה) של $`n`$, ודורשות $`O(\log n)`$ פעולות.

לאורך הסעיף נשתמש בדוגמה רצה: העקום $`E: y^2 = x^3 + x + 1`$ מעל $`\mathbb F_{211}`$. לחבורה $`E(\mathbb F_{211})`$ יש 223 נקודות, וזה מספר ראשוני, ולכן כל נקודה שאינה $`\mathcal O`$ יוצרת את החבורה. ניקח $`P = (0, 1)`$ ונחשב את $`100P`$.

### הכפל-והוסף

השיטה הפשוטה ביותר היא **הכפל-והוסף** (double-and-add), המקבילה של ריבוע-וכפל ב[העלאה בחזקה מודולרית](%D7%94%D7%A2%D7%9C%D7%90%D7%94%20%D7%91%D7%97%D7%96%D7%A7%D7%94%20%D7%9E%D7%95%D7%93%D7%95%D7%9C%D7%A8%D7%99%D7%AA.md). כותבים את $`s`$ בבסיס 2:



```math
s = s_0 + 2s_1 + 2^2 s_2 + \cdots + 2^{n-1}s_{n-1}, \qquad s_i \in \{0, 1\},
```

 כאשר $`n = \lfloor \log_2 s \rfloor + 1`$ מספר הביטים של $`s`$.[^1]

**גרסה איטרטיבית, מהביט הנמוך לגבוה:**

`res ← O          # the point at infinity`  
`temp ← P         # holds 2^i · P`  
`for each bit s_i, from LSB to MSB:`  
`    if s_i = 1:`  
`        res ← res + temp      # point addition`  
`    temp ← temp + temp        # point doubling`  
`return res`

**גרסה איטרטיבית, מהביט הגבוה לנמוך:**

`res ← P                       # corresponds to the MSB, which is 1`  
`for i from n−2 down to 0:`  
`    res ← res + res           # doubling`  
`    if s_i = 1:`  
`        res ← res + P         # addition`  
`return res`

**גרסה רקורסיבית:**

`f(P, d):`  
`    if d = 0: return O`  
`    if d = 1: return P`  
`    if d is odd: return P + f(P, d − 1)`  
`    return f(2P, d / 2)`

מספר ההכפלות הוא $`n - 1`$, ומספר החיבורים הוא מספר האחדות בהצגה הבינארית פחות אחד; בממוצע זה בערך $`n/2`$ חיבורים.

**דוגמה.** $`100 = 1100100_2`$, ולכן



```math
100P = 2(2(2(2(2(2P) + P)) + P)),
```

 כלומר שש הכפלות ושני חיבורים, לעומת 99 חיבורים בשיטה הישירה. בגרסה מהביט הגבוה, הערכים של $`res`$ הם $`P \to 3P \to 6P \to 12P \to 25P \to 50P \to 100P`$. בעקום הדוגמה:

| ביט | פעולה            | $`res`$         | נקודה                      |
|-----|------------------|---------------|----------------------------|
| 1   | התחלה            | $`P`$           | $`(0, 1)`$                   |
| 1   | הכפלה, חיבור $`P`$ | $`2P \to 3P`$   | $`(53, 78) \to (72, 189)`$   |
| 0   | הכפלה            | $`6P`$          | $`(25, 44)`$                 |
| 0   | הכפלה            | $`12P`$         | $`(166, 48)`$                |
| 1   | הכפלה, חיבור $`P`$ | $`24P \to 25P`$ | $`(159, 17) \to (132, 137)`$ |
| 0   | הכפלה            | $`50P`$         | $`(56, 11)`$                 |
| 0   | הכפלה            | $`100P`$        | $`(123, 155)`$               |

למשל, המעבר מ-$`P`$ ל-$`2P`$: השיפוע הוא $`\lambda = (3\cdot 0^2 + 1)/(2\cdot 1) = 2^{-1} = 106`$ ב-$`\mathbb F_{211}`$, ולכן $`x = 106^2 - 0 = 11236 \equiv 53`$ ו-$`y = 106(0 - 53) - 1 \equiv 78 \pmod{211}`$.

שתי הגרסאות האיטרטיביות פגיעות ל**ניתוח תזמון**: זמן הריצה ודפוס הפעולות (הכפלה בלבד, או הכפלה וחיבור) חושפים את הביטים של $`s`$, ש[בקריפטוגרפיה](https://he.wikipedia.org/wiki/%D7%A7%D7%A8%D7%99%D7%A4%D7%98%D7%95%D7%92%D7%A8%D7%A4%D7%99%D7%94) הם בדרך כלל המפתח הסודי. סולם מונטגומרי, בהמשך, הוא חלופה.

### שיטת החלון

בגרסת החלון בוחרים גודל חלון $`w`$ ומחשבים מראש את כל $`2^w`$ הערכים $`dP`$ עבור $`d = 0, 1, \dots, 2^w - 1`$. כותבים את הסקלר בבסיס $`2^w`$:



```math
d = d_0 + 2^w d_1 + 2^{2w} d_2 + \cdots + 2^{mw} d_m,
```

 והאלגוריתם הוא

`Q ← O`  
`for i from m down to 0:`  
`    Q ← 2^w · Q                # w successive doublings`  
`    if d_i > 0:`  
`        Q ← Q + (d_i P)        # using the precomputed d_i P`  
`return Q`

לשיטה הזו אותה סיבוכיות אסימפטוטית כמו להכפל-והוסף, אבל היא משתמשת בפחות חיבורים (שבפועל יקרים מהכפלות). בדרך כלל בוחרים $`w`$ קטן, כך שהחישוב המוקדם זניח; עבור העקומים שהמליץ עליהם NIST, $`w = 4`$ הוא בדרך כלל הבחירה הטובה. עבור סקלר בן $`n`$ ביטים, השיטה דורשת בערך $`n`$ הכפלות ו-$`2^w - 2 + n/w`$ חיבורים.

**דוגמה.** עם $`w = 2`$: $`100 = 1\,21\,00_4`$ בבסיס 4 (כלומר $`100 = 1\cdot 4^3 + 2\cdot 4^2 + 1 \cdot 4 + 0`$). מחשבים מראש $`P, 2P, 3P`$, ואז $`Q: P \to 4P + 2P = 6P \to 24P + P = 25P \to 100P`$.

### חלון מחליק

בגרסת החלון המחליק מחליפים חיבורים בהכפלות. מחשבים טבלה כמו בשיטת החלון, אבל רק עבור $`d = 2^{w-1}, 2^{w-1} + 1, \dots, 2^w - 1`$, כלומר רק עבור הערכים שבהם הביט העליון של החלון דולק. האלגוריתם סורק את ההצגה הבינארית הרגילה של $`d`$: על ביט 0 מבצעים הכפלה בלבד; כשנתקלים בביט 1, לוקחים חלון של עד $`w`$ ביטים שמתחיל בו, מבצעים הכפלות כמספר הביטים בחלון ומוסיפים את הערך המתאים מהטבלה. אם נשארו בסוף פחות מ-$`w`$ ביטים, מסיימים בהכפל-והוסף.

החישוב המוקדם קטן בערך פי שניים מבשיטת החלון הרגילה, והחלפת חיבורים בהכפלות משתלמת. לכן אין כמעט סיבה להעדיף את שיטת החלון הרגילה, פרט לכך שאותה אפשר לממש בזמן קבוע. האלגוריתם דורש $`w - 1 + n`$ הכפלות ולכל היותר $`2^{w-1} - 1 + n/w`$ חיבורים.

### הצגה לא-סמוכה עם חלון (wNAF)

ב**הצגה לא-סמוכה** (non-adjacent form, NAF) מנצלים את העובדה שחיסור נקודה זול כמו חיבור, כדי לבצע פחות פעולות משיטת החלון המחליק. מחשבים קודם את ה-wNAF של המכפיל $`d`$:

`i ← 0`  
`while d > 0:`  
`    if d is odd:`  
`        d_i ← d mods 2^w`  
`        d ← d − d_i`  
`    else:`  
`        d_i ← 0`  
`    d ← d / 2`  
`    i ← i + 1`  
`return (d_{i−1}, …, d_1, d_0)`

כאשר $`d \bmod_s 2^w`$ ("שארית עם סימן") הוא הנציג של $`d \bmod 2^w`$ בטווח $`[-2^{w-1}, 2^{w-1})`$. כל ספרה שאינה אפס היא אי-זוגית ובערכה המוחלט קטנה מ-$`2^{w-1}`$, ולכן מחשבים מראש את הנקודות $`P, 3P, 5P, \dots, (2^{w-1}-1)P`$ (נקודה אחת בהכפלה ו-$`2^{w-2} - 1`$ חיבורים); את הנגדיות שלהן מקבלים בחינם, כי $`-(x, y) = (x, -y)`$. אחר כך:

`Q ← O`  
`for j from i−1 down to 0:`  
`    Q ← 2Q`  
`    if d_j ≠ 0:`  
`        Q ← Q + d_j P          # subtraction when d_j < 0`  
`return Q`

אחרי כל ספרה שאינה אפס יש לפחות $`w - 1`$ אפסים, כי כל חיסור של $`d \bmod_s 2^w`$ מאפס את $`w`$ הביטים הנמוכים של $`d`$. לכן הצפיפות הממוצעת של ספרות שאינן אפס (כלומר של חיבורים) היא $`1/(w+1)`$, מעט טוב יותר מבחלון ללא סימן. מעבר לחישוב המוקדם, האלגוריתם דורש $`n`$ הכפלות ובערך $`n/(w+1)`$ חיבורים. את האפסים שאחרי כל ספרה שאינה אפס לא צריך לשמור, ואפשר להחליף את $`w`$ החלוקות ב-2 בחלוקה אחת ב-$`2^w`$.

**דוגמה.** ה-NAF הרגיל ($`w = 2`$) של 100 הוא $`(1, 0, -1, 0, 0, 1, 0, 0)`$, כלומר $`100 = 128 - 32 + 4`$: יש בו שלוש ספרות שאינן אפס, לעומת שלוש אחדות ב-$`1100100_2`$, אבל הן מופרדות זו מזו. עם $`w = 3`$ מקבלים $`(3, 0, 0, 1, 0, 0)`$, כלומר $`100 = 3\cdot 32 + 4`$; עם הטבלה $`\{P, 3P\}`$ החישוב הוא $`3P \to 6P \to 12P \to 24P \to 25P \to 50P \to 100P`$, עם שני חיבורים בלבד אחרי החישוב המוקדם. בעקום הדוגמה אפשר לבדוק ש-$`128P - 32P + 4P = (123, 155)`$, כמו בטבלה.

הוכח שהתקפת ערוץ צדדי מסוג FLUSH+RELOAD על המימוש של wNAF ב-[OpenSSL](https://he.wikipedia.org/wiki/OpenSSL) מאפשרת לשחזר את המפתח הפרטי המלא אחרי מדידת תזמוני מטמון של 200 חתימות בלבד.[^2]

### סולם מונטגומרי

**סולם מונטגומרי** (Montgomery ladder)[^3] מחשב את הכפל במספר **קבוע** של פעולות. זה מועיל כאשר תוקף מבצע [התקפת ערוץ צדדי](https://he.wikipedia.org/wiki/%D7%94%D7%AA%D7%A7%D7%A4%D7%AA_%D7%A2%D7%A8%D7%95%D7%A5_%D7%A6%D7%93%D7%93%D7%99) ויכול למדוד תזמון, צריכת הספק או הסתעפויות. האלגוריתם משתמש באותה הצגה בינארית $`d = (d_m \dots d_0)_2`$ כמו הכפל-והוסף:

`R0 ← O`  
`R1 ← P`  
`for i from m down to 0:`  
`    if d_i = 0:`  
`        R1 ← R0 + R1`  
`        R0 ← 2·R0`  
`    else:`  
`        R0 ← R0 + R1`  
`        R1 ← 2·R1`  
`return R0`

האינווריאנט הוא $`R_1 = R_0 + P`$ לאורך כל הריצה: אם אחרי עיבוד הביטים העליונים $`R_0 = kP`$ ו-$`R_1 = (k+1)P`$, אז אחרי ביט 0 מקבלים $`(2k)P, (2k+1)P`$, ואחרי ביט 1 מקבלים $`(2k+1)P, (2k+2)P`$. בכל צעד מבוצעים חיבור אחד והכפלה אחת, בלי תלות בערך הביט, ולכן ברמה הזו האלגוריתם אינו מדליף מידע דרך הסתעפויות או צריכת הספק. המהירות שלו דומה לזו של הכפל-והוסף.

**דוגמה.** עבור $`d = 100 = 1100100_2`$, הזוג $`(R_0, R_1)`$ עובר דרך



```math
(P, 2P) \to (3P, 4P) \to (6P, 7P) \to (12P, 13P) \to (25P, 26P) \to (50P, 51P) \to (100P, 101P),
```

 ובעקום הדוגמה $`R_0`$ מסתיים ב-$`(123, 155)`$.

עם זאת, הוכח שהתקפת FLUSH+RELOAD על OpenSSL מאפשרת לשחזר את המפתח הפרטי המלא אחרי מדידת תזמוני מטמון של חתימה אחת בלבד, בעלות נמוכה מאוד.[^4]

### שרשראות ארוכות יותר

שימוש בשרשראות לוקאס נותן סדרה מיטבית יותר של הכפלות וחיבורים מאשר סולם מונטגומרי, ומהירה יותר עבור מכפילים גדולים. השיטה נקראת PRAC, וגם היא פורסמה על ידי מונטגומרי; המימוש המרכזי שלה הוא בתוכנה GMP-ECM. ברנשטיין ולנגה סקרו ב-2017 כמה שיטות כאלה.[^5]

### סולם מונטגומרי בזמן קבוע

מימושים קריפטוגרפיים חשופים להתקפות תזמון, שמנצלות את התלות של זמן הריצה בנתונים: זמן העיבוד משתנה עם הקלט, ולכן גם עם המפתח. כדי למנוע זאת כותבים מימושים **בזמן קבוע**. לפי ההגדרה של ברנשטיין, מימוש תוכנה הוא בזמן קבוע אם הוא נמנע מכל הסתעפות שתלויה בקלט, מכל אינדקס מערך שתלוי בקלט, ומכל הוראה אחרת שזמן הביצוע שלה תלוי בקלט.[^6]

על [עקומי מונטגומרי](%D7%A2%D7%A7%D7%95%D7%9D%20%D7%9E%D7%95%D7%A0%D7%98%D7%92%D7%95%D7%9E%D7%A8%D7%99.md) $`By^2 = x^3 + Ax^2 + x`$ אפשר לבצע את הסולם בעזרת קואורדינטת $`x`$ בלבד, בקואורדינטות השלכתיות $`\langle X : Z \rangle`$ (עם $`x = X/Z`$). הסולם הנאיבי מכיל הסתעפות שתלויה בביט סודי, ולכן הוא אינו בזמן קבוע. הפתרון המקובל הוא **החלפה מותנית** (CSwap): פונקציה שמחליפה בין שני זוגות $`\langle X_2, Z_2\rangle`$ ו-$`\langle X_3, Z_3\rangle`$ אם ורק אם $`b = 1`$, בלי להדליף את $`b`$ (למשל בעזרת מסכות ביטים). אחרי ההחלפה, צעד הסולם תמיד מכפיל את הזוג הראשון ומחבר את שניהם:

`Montgomery-Ladder(x_P, n):        # n has l bits`  
`    X1 ← x_P`  
`    X2 ← 1; Z2 ← 0                 # the point at infinity`  
`    X3 ← x_P; Z3 ← 1               # the point P`  
`    prevbit ← 0`  
`    for i from l−1 down to 0:`  
`        bit ← bit i of n`  
`        b ← bit XOR prevbit`  
`        prevbit ← bit`  
`        (⟨X2,Z2⟩, ⟨X3,Z3⟩) ← CSwap(⟨X2,Z2⟩, ⟨X3,Z3⟩, b)`  
`        (⟨X2,Z2⟩, ⟨X3,Z3⟩) ← Ladder-Step(⟨X2,Z2⟩, ⟨X3,Z3⟩, X1)`  
`    (⟨X2,Z2⟩, ⟨X3,Z3⟩) ← CSwap(⟨X2,Z2⟩, ⟨X3,Z3⟩, prevbit)`  
`    return X2 · Z2^(p−2)`

בערך המוחזר, $`Z_2^{p-2}`$ הוא $`Z_2^{-1}`$, שמחושב לפי [המשפט הקטן של פרמה](https://he.wikipedia.org/wiki/%D7%94%D7%9E%D7%A9%D7%A4%D7%98_%D7%94%D7%A7%D7%98%D7%9F_%D7%A9%D7%9C_%D7%A4%D7%A8%D7%9E%D7%94) (גם החישוב הזה הוא בזמן קבוע). ההחלפה המותנית שאחרי הלולאה הכרחית: בלעדיה, כאשר הביט הנמוך של $`n`$ הוא 1, הפונקציה מחזירה את קואורדינטת ה-$`x`$ של $`(n+1)P`$ במקום של $`nP`$.[^7]

הפונקציה Ladder-Step היא לב האלגוריתם: שילוב של **חיבור דיפרנציאלי** (חישוב $`x(R+S)`$ מתוך $`x(R)`$, $`x(S)`$ ו-$`x(R - S) = x_P`$) והכפלה. הקבוע $`a_{24}`$ מוגדר כ-$`(A+2)/4`$, כאשר $`A`$ הפרמטר של עקום מונטגומרי:

`Ladder-Step(⟨X2,Z2⟩, ⟨X3,Z3⟩, X1):`  
`    A  ← X2 + Z2;   B  ← X2 − Z2`  
`    C  ← X3 + Z3;   D  ← X3 − Z3`  
`    AA ← A²;        BB ← B²`  
`    DA ← D · A;     CB ← C · B`  
`    X3 ← (DA + CB)²`  
`    Z3 ← X1 · (DA − CB)²`  
`    X2 ← AA · BB`  
`    E  ← AA − BB`  
`    Z2 ← E · (BB + a24 · E)`  
`    return (⟨X2,Z2⟩, ⟨X3,Z3⟩)`

כאן $`\langle X_2 : Z_2\rangle`$ החדש הוא $`x(2R)`$ ו-$`\langle X_3 : Z_3\rangle`$ החדש הוא $`x(R + S)`$. אפשר לבדוק את נוסחת ההכפלה: $`AA \cdot BB = (X^2 - Z^2)^2`$, ו-$`E = 4XZ`$, ולכן $`E(BB + a_{24}E) = 4XZ\bigl((X - Z)^2 + (A+2)XZ\bigr) = 4XZ(X^2 + AXZ + Z^2)`$, בהתאם לנוסחה $`x(2R) = \frac{(x^2 - 1)^2}{4x(x^2 + Ax + 1)}`$. ב-RFC 7748 משתמשים בניסוח שקול עם $`a_{24}' = (A-2)/4 = 121665`$ ו-$`Z_2 = E(AA + a_{24}'E)`$.

חלופה זולה יותר להחלפה מותנית היא **בחירה מותנית** (CSelect), שנידונה באופן פורמלי בעבודה של נת' וסרקר.[^8]

### מימושים

מאז הצגת העקום הסטנדרטי Curve25519 ברמת ביטחון של 128 ביט נכתבו מימושים רבים של הסולם, רבים מהם ב[שפת סף](https://he.wikipedia.org/wiki/%D7%A9%D7%A4%D7%AA_%D7%A1%D7%A3) של הארכיטקטורה, כדי להשיג ביצועים מרביים. ברנשטיין, דאיף, לנגה, שוואבה ויאנג כתבו ב-2012 מימושים בני 64 ביט לארכיטקטורת AMD64 בעזרת הכלי qhasm, ובהם השתמשו ב-CSwap. מאוחר יותר הופיעו מימושים שכתובים ביד, שבהם השתמשו ב-CSelect, ומימושים שמשתמשים בהוראות וקטוריות (SIMD). יש גם מימושים יעילים לארכיטקטורת ARM. הספריות lib25519 ו-s2n-bignum כוללות מימושים יעילים של הסולם עבור Curve25519. מימושים יעילים נחקרו גם עבור העקום Curve448 (רמת ביטחון של 224 ביט), עבור Curve41417 (מעט יותר מ-200 ביט), ועבור עקומי מונטגומרי אחרים ברמות ביטחון של 128, 224 ו-256 ביט.
